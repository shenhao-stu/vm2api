# 固定出口 IP 保护

这是原生 `kin-egress` 的可选严格模式。默认关闭以保持原有部署行为；启用后没有明确预期 IP 的代理不可用于业务。预期 IP 保存在 SQLite `settings.proxy_exit_guard`，不来自 `geo_ip`、订阅地址或健康检测结果。订阅刷新不能改写它。

## 行为与边界

- 每次建立业务 TCP 连接、处理 DNS 查询前，通过该代理的 SOCKS 链路访问 HTTPS IP 检测服务；禁止重定向、证书校验失败、非法响应、超时或 IP 不一致均阻断。
- 默认每 15 秒复核运行中的出口，一次验证总时限 10 秒。网络 EOF/超时/连接错误及检测端 429/500/502/503/504 最多尝试 3 次，间隔 250ms，共用该时限。复核期间使用原生 checking 状态阻断新连接，已有流只在这个有界窗口内保留；同 IP 验证成功后继续，持续失败则锁存并关闭连接、告警和停止槽位。
- IP 不一致、证书错误、重定向和非法响应立即锁存，不通过重试接受新 IP。单个业务请求取消不代表共享代理损坏，已开始的验证由守卫在上述时限内独立完成；取消的业务请求仍返回取消。诊断 `probe.attempts` 记录这次验证的尝试次数。
- 主机侧凭据转换使用同一个 helper 的回环 SOCKS 入口，不能通过请求体 `proxy_url` 覆盖绕过。
- 锁存不会因普通健康探测、返回旧 IP 或服务重启而自动解除。相同策略 revision 的 helper 重启也要求管理员重新验证，包含正常维护重启。
- 严格模式暂不支持本机直出、远程节点、Codex 槽及无槽位的 API endpoints；这些路径拒绝请求。远程图片 URL 也拒绝，使用内联图片数据。严格模式不会隐式回退到宿主机直连。
- 浏览器打开的外部 OAuth 授权网页不在服务端出口控制范围内。
- IP 检测和业务访问是不同连接及目的地。代理商可以按连接或目标分配出口，因此该保护只能对观测结果失败关闭，不能证明所有业务连接具有相同公网 IP。需要供应商提供可信的固定出口保证；本功能不保证账号不被封禁。

## 管理接口

使用已有管理员认证，所有接口均 `Cache-Control: no-store`，非管理员返回 403。不得把管理员 key 写进脚本仓库或日志。

| 操作 | 接口 | JSON |
| --- | --- | --- |
| 查看配置及安全状态 | `GET /api/panel/proxy-exit-guard` | 无 |
| 全局要求强校验 | `PUT /api/panel/proxy-exit-guard` | `{"required":true}` |
| 明确指定某代理预期 IP | `PUT /api/panel/proxy-exit-guard/<proxy-id>` | `{"expected_ip":"203.0.113.10"}` |
| 人工重新验证相同预期 IP | `POST /api/panel/proxy-exit-guard/<proxy-id>/rearm` | `{"expected_ip":"203.0.113.10"}` |

上表 IP 仅文档示例。新订阅的入口服务器 IP 不等于出口 IP，不能自动拿入口或探测结果填入预期值。

配置修改前会停止相关槽和出口连接；仅重新启动出口 helper，不恢复槽或凭据。相同 IP 的 PUT 幂等，不会解除已有锁存。`rearm` 必须再次提交当前预期 IP；填写不同值返回 409，需要管理员单独明确修改预期 IP。不要把 rearm 放进自动巡检、重启脚本或失败重试逻辑。

启用顺序：停止旧业务 → 全局 required=true → 管理员明确设置预期 IP → 查看 helper 独立验证结果 → 在账号合法可用的前提下人工启动槽。已封禁或撤权账号不得因此被恢复。

## 告警

代理页面显示指定 IP、最近观测、阻断原因。控制面每 5 秒读取安全状态；对于已配置或已绑定的异常出口，写日志并调用现有通知系统，同一故障每 5 分钟最多通知一次。未绑定且未指定 IP 的订阅候选只显示未配置，不批量刷告警。

原生通知支持飞书群机器人（`notify.feishu.enabled`、`notify.feishu.webhook`）。Webhook 只允许官方 HTTPS bot endpoint，禁止重定向，8 秒超时；GET 隐藏地址，仅返回 `webhook_set`。保存空地址保留已有密钥。通过设置页“发送测试”验证实际送达；失败不会解除出口阻断。原生邮箱、Telegram、企业微信渠道继续保留。

## 验收与维护

用模拟 TLS IP 服务、模拟 SOCKS 和本地目标验收：正确 IP、两个并发流、不一致、检测异常、活动连接关闭、重启锁存、人工 rearm、未配置与不支持路径、通知失败和秘密脱敏。不要为了出口验收调用封禁账号。

更新 helper 二进制或重启生产服务后，先检查锁存状态；需人工重新验证时不能由部署脚本自动确认新 IP。保留 `data/run/egress/<proxy-id>/exit-guard-state.json` 与 SQLite 策略，不能通过删状态目录“修复”。备份恢复不得重新引入已退休账号的凭据或虚拟机。
