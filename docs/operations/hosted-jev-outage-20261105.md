# Hosted JEV organization deactivation

The five new Claude failures on 2026-11-05 came from JEV before any Claude dispatch: all had `via=jev`, zero attempts and no VM. Read-only model-catalog requests for all 50 configured TypeSafe keys returned HTTP403 with structured `authentication_error` and `Your organization has been deactivated`. One synthetic SystemOne request confirmed the same response. This is a JEV organization failure, not evidence of Claude account suspension or a kernel regression.

Recognize only confirmed authentication/organization failures as dead credentials. An arbitrary403 or HTML/WAF page must not retire keys. Read error bodies with an8KiB bound and release them; persist only endpoint-scoped SHA256 fingerprints and allowlisted reasons in `jev_key_health`. Restart retains retirement; saving unrelated configuration does not rearm. Explicitly saving credentials still allows the operator to retry after confirmed provider recovery. Other valid credentials on the endpoint retain bounded failover.

Fail-closed service outages now return503 `moderation_unavailable`, with zero model dispatch and no device ban/refusal-memory write. Actual content refusals keep their existing policy contract. Historical `policy_blocked` rows with the exact decision-service-unavailable message classify as upstream failures and count against SLA; the original ledger is not rewritten. The JEV usage view prioritizes confirmed organization retirement over stale successful usage.

Keep existing local rules, refusal protection, Fable exclusion, DSH-off, per-slot circuit, fixed egress and manually paused slots. Do not silently change fail-closed to fail-open. Restoring model service requires valid reviewer credentials or an explicit operator decision to change external-review policy; code cannot reactivate the provider organization. Never include full provider errors, request text or API keys in ordinary health statistics.

Evidence: managed project `work/claude-errors-20261105/`. Synthetic tests cover retirement/no repeat, same-endpoint healthy-key failover, restart persistence, scoped fingerprints, ordinary403/oversized-body protection, API503/no-ban semantics, historical classification/SLA and panel state. The Mac remote-telemetry fixture is a previously reproduced baseline issue; production Linux verification is authoritative for that fixture.
