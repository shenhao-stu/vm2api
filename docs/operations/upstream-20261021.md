# v1.3.202 and asynchronous backups

Integration base: fork `d34cc252338c`, upstream `33e1f0a6158f0363d1816bcee9223cc134a3098f` (v1.3.202 plus #639).

This merge adopts upstream credential reconciliation, login refresh exclusion, tenant ownership checks, thinking-signature ownership and worker-thread backups. It preserves encrypted proxy subscriptions, strict exit-IP guards, guarded host OAuth, deployment telemetry opt-out, private key scopes, quota handling, bounded retries, stream accounting and lifecycle rollback.

The login readiness API and shell ticket issuance are now asynchronous. Keep the existing strict exit check before local or remote container access, await readiness at both ticket issuance and WebSocket acceptance, and preserve the guard's safe status and reason. Strict mode continues to reject unsupported remote exits.

The CLI still reports 2.1.296, but its pinned bytes changed. Verify the manifest SHA, synchronize only the intended slot using the native wrap sync endpoint, and verify the executing payload after the controlled reload. Do not infer running-version parity from a version string or the file on disk alone.

## Optional privacy settings

Use the existing slot `seed_policy.extra_env` through `PUT /api/panel/vms/:id/seed-settings`. Merge these entries with existing extra settings:

```json
{
  "extra_env": {
    "DISABLE_ERROR_REPORTING": "1",
    "DISABLE_FEEDBACK_COMMAND": "1",
    "CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY": "1"
  }
}
```

Keep `VM2API_DISABLE_TELEMETRY=1`, generated `DISABLE_TELEMETRY=1` and `DO_NOT_TRACK=1`, and disabled worker telemetry. Do not request `telemetry_service_restart` solely to save these keys: that action also restarts the egress helper. Apply them before the planned slot process reload, then read back persisted and generated settings. They control optional reporting, not inference content, account enforcement or every request field. See [Anthropic data usage](https://code.claude.com/docs/en/data-usage).

## Release invariants

- Build and test without production credentials, network access or the Docker socket inside the test container.
- Compare all fork-only changes against the previous production revision, not just merge-conflict files.
- Drain requests through native scheduling controls before swapping the gateway. Retain slot containers, HOME, credentials, network and approved proxy identity.
- Keep key, slot and downstream account concurrency at 1. Keep dedicated key allowlists and downstream exclusive groups.
- Never automatically accept another IP or clear an exit-guard latch. If a planned restart requires rearming, leave requests blocked until an operator verifies the unchanged approved exit and explicitly performs the guarded recovery. Unrelated stopped or retired accounts remain stopped.
- Preserve runtime configuration and secrets; do not overwrite them with repository defaults. Rollback must not restore expired or retired account snapshots.
- Verify JSON and complete SSE termination, effective account attribution and guard state after rollout. Report skipped or unavailable tests separately.

`BackupService.createBackup` and `restoreBackup` now return promises. Callers must await them. The backup worker owns its database connection; snapshot/hash/archive work no longer blocks the gateway event loop. Restore is still a maintenance operation.
