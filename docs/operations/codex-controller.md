# 独立 Codex 控制器接入

Claude 与 Codex 可以共享控制台入口，同时保留独立后端。主控制器继续管理 Claude / ReClaude；Codex 控制器管理自己的账号、OAuth、数据库、配额和日志。更新 Codex 不需要重建 Claude 内核或重启现有槽。

## 管理与网络

- 控制台通过 `?controller=codex` 选择 Codex，切换时完整导航，避免缓存混用。
- 管理桥先调用主控制器的原生管理员鉴权；Codex 管理密钥只保留在服务端。匿名、非管理员和跨源写入应被拒绝。
- Sub2API 通过受限私网桥访问 `/codex/v1/*`，管理接口不进入这条桥。不要扩大来源网段或公开内部监听端口。
- 每个账号使用独立 OAuth、HOME、会话和固定代理。出口不符或守卫锁存时保留阻断，不自动接受新 IP。

Codex 使用独立原生转发内核。槽记录中的 `stopped` 是兼容 Claude 容器生命周期的旧字段，不代表 Codex 转发内核停机。就绪判断使用原生 `isCodexSlotReady`、凭据、代理、配额及调度状态；不要为了改变此字段而启动无用的占位容器。

## Sub2API 接入

统一上游 Key 可以使用 Codex 控制器的原生 `all` 分组，后续账号自动纳入。账号并发仍由每个 Codex 槽限制，不把统一 Key 当作下游用户身份。

Sub2API 的 OpenAI API Key 账号启用 `openai_relay_session_scope` 后，按认证用户、Key 和受信接入层身份划分会话命名空间。接入层必须先移除客户端伪造的身份头，再写入认证身份。只有经核实的内部 Key 可以声明此身份。`previous_response_id` 和不透明续接状态仍需归属校验；不能仅改会话名。尚未覆盖同等隔离的 WebSocket 路径应保持关闭。

推广前使用独立临时组完成：同名会话的双 Key 隔离、工具调用、历史续接、SSE 完成事件、跨用户续接拒绝，以及唯一账本记录。验收后删除临时 Key、分组和授权，保留消费证据。

## 图片计费与额度

Image 2.6 的 token 价格存在，不等于图片接口一定走 token 计费。Sub2API 原生图片分支在没有精确 token 价卡时，仍可能回退到通用按张价格。

对于 `gpt-image-2.6-flare` 和 `gpt-image-2.6-sunburst`，在目标组添加精确模型价卡，设置 `billing_mode=token`。价格留空可继承已有目录的五个计量桶：文本输入、缓存文本输入、图像输入、缓存图像输入、图像输出。保持其他模型价格、倍率、图片权限与渠道优先级不变。用真实响应终量与账本核对，不能只看 HTTP 200。

图片额度存入独立 `codex.image_usage`，其每日窗口和冷却不能覆盖文本 5H / 7D。官方没有提供的窗口显示未知，不填成 0%。积分回退沿用原生策略；重置卡只能由明确的管理操作兑换。

## 升级验收

先记录现有容器身份、启动时间、出口和资源，再发布独立 Codex 控制器。为其设置独立内存、CPU、PID 和堆上限；当前空闲内存不是任意并发、长上下文或大图输出的容量保证。

用新请求验证完整终态与计量，不重放已派发或消费状态不明的请求。分别记录预期的前置拒绝与真实故障。发布后复核旧服务生命周期、固定出口、错误日志和自然请求；短时成功不能证明永久稳定。
