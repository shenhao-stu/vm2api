# Codex 质量检测、静置与后台开销

这组功能从本机保存的 C2A 二开源码适配到 `dev/hosted`，没有切换部署架构。Claude 的调度器、请求体上限、长请求计时、多轮工具历史、账号并发和取消流程保持原实现。

## 质量筛查

管理员在「设置 → OpenAI → GPT 质量检测与静置恢复」配置和查看检测。默认关闭；启用后会使用账号额度，默认探测并发为 1，每 15 分钟一轮。模型必须是已启用的 GPT/Codex 模型，Fable 和 Claude 模型禁止用于此检测。检测走现有网关的固定账号 Responses 路径，遵守账号席位上限，不因 401 自动刷新凭据，也不会换号后将结果记给原账号。

连续两次有效的完整错误答案会暂停该账号。网络错误、429、空答案、未完成或截断的答案均不计答错。单道题的表现只能作为质量异常线索，不能证明模型身份或普遍能力下降；检测题目和阈值可以修改。

另外保留上游 `safety_buffering` 的严格布尔值观测：配置响应头、字符串 `"true"`、缺少信号均不能当作实际触发。明确触发且请求的不是 Luna 模型时可暂停目标账号；显示的上游模型名也是观测值。状态与账号身份绑定，换号或修改题目后旧答案失效；普通令牌轮换保留同一账号的证据。旧式多账号槽会跳过质量检测，避免把其他账号的结果归到第一份凭据；业务请求保持原行为。

## 静置与恢复

质量暂停后静置 24 小时，随后只复测到期账号。第一次答对后继续暂停，至少隔 10 分钟第二次答对才恢复；失败或技术错误重新静置 24 小时。进度和到期时间持久化，重启不会跳过静置。恢复只解除本功能自己的暂停原因，保留人工关闭、认证失效、代理、额度和工作时段限制。现有熔断与冷却继续生效。

关闭检测时不再派发新检测或恢复请求，已派发请求等待有界超时后结束，其旧结果不再改变调度状态；已有质量暂停保留。配置损坏或模型不合法时也按关闭处理。未配置时没有新增付费后台探测。

## 请求与后台开销

- 模型目录按账号结果增量合并，保留其他账号可见模型、管理员编辑、Fast 别名和图片模型开关；新发现模型默认关闭。旧面板草稿不能覆盖新目录事实。
- 相同目录扫描共用一个任务，最多六次尝试、三个成功账号、总计 60 秒；请求头和响应正文均有超时。后台不刷新 OAuth，跳过静置、忙碌、认证/人工暂停及额度冷却账号，并在派发前重查。GPT 后台目录刷新维持原有 6 小时间隔，没有采用参考实现更频繁的 15 分钟。
- Codex 内核健康证明最多复用 2 秒，只适用于当前进程持有的存活子进程；配置、令牌、socket、进程代次变化及传输故障会使证明失效。重叠健康检查共用一次 socket 请求。账号/代理/额度检查仍逐请求执行。
- 控制台状态流省略相同快照，慢客户端仅标记需要重发的最新状态，排水后重读；持续 30 秒不能排水则断开。不会积累无界状态队列，也不增加每个客户端的高频文件轮询。
- 日志保留清理按最多 1,000 条的小事务执行，批次之间让出事件循环；清理中断保留覆盖缺口标记，避免错误推算额度。数据库恢复或关闭前停止并等待清理。保留原有异步写入、密钥哈希、正文捕获限制、工具恢复统计和计费字段。

没有引入参考服务的多进程 runtime owner、跨进程租约、自动换出口、密码保险库或 ReClaude，也没有升级 Claude 内核。这些能力涉及单独的部署或账号生命周期迁移，不能通过覆盖调度器安全获得。

管理接口仅管理员可用：`GET/PUT /api/panel/quality-probe`，`POST /api/panel/quality-probe/run`。手动启动同样要求配置已开启；重复启动返回冲突。接口只展示检测题目的统计与结果，不收集用户会话正文。

## 固定出口的 Codex 控制器

在专用控制器设置 `VM2API_CODEX_QUALITY=1`，并在持久化数据目录创建 `codex-quality-exits.json`，每个槽登记经过核验的 SOCKS 入口和固定出口。

```json
{
  "codex-example": {
    "proxy_id": "example-proxy",
    "host": "127.0.0.1",
    "port": 1080,
    "ip": "192.0.2.10"
  }
}
```

VM 页和高级设置共用同一个探测器。VM 页支持手动、每小时和每天。首次升级会核对槽内账号身份，并沿用上一次派发时间。两个 HTTPS 见证必须都经过该 SOCKS 并返回登记的地址才能发起模型请求。探测使用独立请求 ID 和会话，最多 512 个输出 token；完整响应、单次派发、模型和指定槽的账本一致才判分。手动执行同样遵守已启用的自动间隔。进程在恢复探测中途退出且存在未决派发时，再静置 24 小时。业务请求可以继续使用其他席位。
