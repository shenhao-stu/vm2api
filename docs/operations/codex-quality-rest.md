# Codex 答题质量与静置恢复

在 vm2api 原生 VM 页提供 GPT 探测结果、缓冲信号、静置时间和恢复日志；沿用项目组件及主题，不引入 C2A 页面。设置页和 VM 页共用查询与结果组件。Claude / ReClaude 不展示或参与 GPT 探测。

## 状态与约束

- 默认关闭；启用后只测空闲且具备有效凭据的 GPT 账号。生产沿用每账号每小时一次、探测并发1；这与业务每账号并发10是两个不同设置。
- 默认连续两次有效答错暂停调度，24小时后复测；首次答对仍暂停，至少10分钟后再次答对才恢复。恢复阶段失败重新静置。
- 网络错误、429、无效答案不增加也不清空连续答错。请求派发意图与账号身份持久化，未知终态不重复派发。
- 非 Luna 请求明确返回布尔值 `safety_buffering: true` 才作为独立暂停信号。未提供、字符串 `"true"` 均视为未知。配置备用模型不代表发生模型切换，答题结果也不能证明模型身份。
- 只有同一目标账号、一次派发、已验证完成的响应可贡献信号。响应模型不符时保留已归属的独立缓冲信号，但答案不参与计分。
- SSE 仅提取两个配置头：`x-codex-safety-buffering-enabled` 与 `x-codex-safety-buffering-faster-model`，最多200字符；不传播其他头或认证数据。先观察到 true 不被后续 false 覆盖。
- 手动恢复复用原生调度 API，携带 `expected_reason=quality_probe_failed`。暂停原因发生变化时返回409；只解除质量暂停，保留人工停用、凭据、额度、工作时段及出口限制。
- 停调度不终止在途请求。出口锁不能通过质量恢复解除；新IP必须单独授权。

## 发布边界

GPT 控制器与 Claude / ReClaude 独立发布。仅将审核过的 Codex 源文件覆盖到当前生产镜像，不全量替换另一服务，也不更换 Claude CLI / 内核。

发布顺序：核对当前版本和并行发布锁 → 验证原固定出口 → 暂停目标上游入口 → 原生 hold 排空 → 更新独立 Codex 容器 → 对比凭据/配置/质量记录/并发/其他容器生命周期 → 再次验证原出口 → 仅撤销本次维护 hold → 恢复原上游入口。失败回滚，禁止自动接受新IP或重新派发已消费请求。

统一控制台使用其现行 main 基础静态构建，复用本分支的质量组件；保留 `VITE_CODEX_CONTROLLER=true` 和 `controllers.json` 的 main/codex 双入口。先上传不可变 assets，最后用旧 index SHA 比较后原子发布 HTML，无需重启 Claude 网关。独立 hosted VM 页只在 GPT-only 控制器显示质量卡片。

## 验证

覆盖 SSE 信号与配置分离、错误计分、静置双阶段恢复、账号身份变化、忙碌跳过、取消和无重放、人工/出口限制、手动恢复竞争保护。前端渲染不能触发模型调用；执行中禁用重复探测。

2026-11-08发布候选：Linux581项、hosted前端639项、统一控制台519项通过。初次混用版本测试暴露5项旧Codex工具历史转换缺失，采用分支已有原生转换修复；另1项旧模型目录断言与生产保留目录策略不符，改用当前测试核验“不混入图像模型，保留已有目录”。原失败记录与基线对照保留在项目工作证据中。
