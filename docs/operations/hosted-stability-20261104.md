# Hosted cache lifecycle and slot isolation

Keep `compatibility.preserve_pruned_tool_results` false on managed. The cache now expires idle entries using an unrefed nearest-deadline timer. Disable, restore-to-disabled, and shutdown clear retained originals and invalidate pending snapshots; old completions cannot repopulate the cache or disturb a new session transaction. In-flight model execution is not cancelled by a configuration change.

Migration 049 adds only `tool_prune_reason`, `tool_prune_restored`, and `tool_prune_restored_bytes` to ordinary usage summaries. Values are allowlisted categories and nonnegative integer counts; original text, session values and credentials are not copied into these metrics. Existing user/time-scoped stats expose outcomes, byte increases, cache tokens, errors and mean latency without enabling debug body capture. These are observations, not a claim of causal cost savings.

The existing unit circuit now also counts attributable kernel, transport, timeout, empty and interrupted-stream failures, including known upstream failures after output starts. Replay permission remains independent: uncertain upstream execution is never replayed merely because the circuit opens. Client errors/cancellation, quota/RPM, overload capacity, credential death and proxy outages retain their dedicated gates. Managed policy is three consecutive qualifying failures, five minutes open, then one half-open request; another failure reopens it and verified success restores it. Explicit organization disable/revoked credentials stay parked by existing stronger gates. Manual scheduling/exit locks are not cleared.

Include the narrow terminal-error fix from shenhao-stu/main commit `c1a38686` (PR 11): an unfinished Anthropic stream emits its mapped terminal error even after content starts, while preserving valid truncation handling. Native ReClaude relay remains excluded.

Read-only comparison on 2026-11-04: getoken/main pins kernel `8f1347cc` and cli-node `55efe49e` from the preserved October payload; managed pins kernel `f57d4e71` and cli-node `8484c4c5` from November. cc-node is identical (`be5eec49`). The retained getoken Pro logs contain 8202 successful rust-kernel-stream rows and various quota/network/kernel errors; managed has 24 successful Claude rows. These different workloads and observation windows cannot establish that the newer kernel causes account bans. The explicit disabled/banned message scan found no such rows in the audited error subset; it is not an account-lifecycle census.

Keep managed's already verified binaries pinned and `KIN_AUTO_SYNC_WRAP=0`; do not speculate by rolling five accounts to an untested old payload or copy getoken's production overlays. This release changes the Node control plane, lifecycle/metrics and slot isolation, not kernel binaries, identity, OAuth, proxy bindings, GPT or main. Four proxy bindings currently resolve to the same exit IP; preserve the user's approved bindings and make no claim of independent network failure domains or guaranteed ban prevention. Account/organization disable, permanent credential revoke and fixed-IP drift require their existing stop/hold paths, not repeated retries.

Validation uses synthetic faults and fake clocks, followed by Linux release-image regression and a small permitted-model acceptance. Never call Fable. The deployment closes admission, drains requests, takes a consistent backup, replaces only the hosted gateway, verifies the original IP guards and restores only previously active admission. Keep migration-compatible rollback image and backup; never restore an old usage database over new traffic.
