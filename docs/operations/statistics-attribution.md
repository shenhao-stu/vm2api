# 统计页的槽位归属

统计 API 的 `vm` 维度按 `usage_logs.vm_id` 聚合，代表槽位，不是外部供应商目录。`__none__` 表示这个字段为空；它不是一个真实槽位，也不能单凭此值认定请求发送给了未知上游。控制台统一显示为“未归属槽位”，图例、提示和排行共用同一名称函数。

排查该分组时，对同一时间窗口交叉核对：

- `usage_logs` 的 `attempt_count`、HTTP 状态、`final_state`、`error_code` 和计量字段；
- 相同 `request_id` 的 `request_attempts`；
- 原生日志页的供应商链。明确零次尝试且没有供应商链的行显示“未发送上游”。

额度保护、无可用账号、参数或拒绝保护可在分配槽位前结束。原生预热拦截也可能在本地成功应答。因此“未归属槽位”既不等于全部失败，也不等于全部零费。历史尝试信息缺失时应保留不确定性。已删除但仍有 `vm_id` 的槽位继续显示其 ID，不应并入空归属分组。

展示修复不删除错误、不猜补 `vm_id`、不改计量或账本。聚合后的统计接口不含逐条尝试证据，不能把整个空归属分组直接改名为“未发送上游”。用户/密钥/模型维度的空归属也不能借用槽位标签。

## 只更新控制台时

如果后端契约未改，可验证并热发布已构建的静态资源，避免为了文案和显示逻辑重启代理、网关或槽位。先放置新的内容哈希资源并校验，再原子替换 `index.html`；保留旧哈希资源供已打开的页面使用。原生静态服务对 HTML 使用 `no-store`，哈希资源保持不可变。

同时保存前一入口、构建来源和资源摘要，并将相同产物加入基于当前安全镜像的可重建发布镜像，更新部署清单的目标镜像。不要把运行容器的临时文件替换误当成持久发布。分别记录仍运行的后端镜像、实际静态资源版本和下次重建目标；此流程不执行 `compose up`、槽位重载或出口守卫解锁。

验收包括原页面复现、静态资源摘要、请求/错误/计量总数不变，以及网关、槽位、代理守卫和下游账号策略不变。统计显示修复无需重放任何收费模型请求。
